About

I'm a third-year CS student working the defensive side of security — detection engineering, SIEM operations and endpoint telemetry.

I build small systems that force me to learn how detection actually works underneath the dashboard: what counts as a signal, when it's allowed to fire, and why most of them shouldn't. Several of my projects are independent attempts at the same hard problem — separating real attacker behaviour from the enormous amount of ordinary software that merely looks suspicious.

Outside of that: CTFs, a Wazuh home lab, and running a security study jam for students at my college who have never touched this before.

How I think about detection

Capability is not intent.Plenty of trusted software installs keyboard hooks, opens raw sockets, reads the clipboard. Flagging capability alone builds a tool analysts learn to ignore.
Persistence amplifies risk.A single observation is a data point. Behaviour that survives over time is a signal.
Every signal explains itself.If I can't say why something scored what it did, nobody can triage it. A model score only amplifies a rule that already fired.
Correlation beats volume.One high-confidence incident from a complete attack chain is worth more than a thousand isolated alerts.

Selected work

ambit

A provenance and control plane for Claude Code agents and the MCP servers they connect to, built in response to documented attacks: s1ngularity (malicious npm packages re-invoking installed AI CLIs to exfiltrate credentials) and GTG-1002 (an espionage campaign decomposed into thousands of innocuous agent subtasks).

An endpoint daemon holds everything needing a live, sub-millisecond verdict; Wazuh is the fleet plane for correlation and alerting and never sits in the synchronous path. M0, the observation layer, is complete and tested; later milestones are design only.

GoWazuhMCP

keyboard-hook-behavioral-detector

Finds processes capable of keylogging and scores how suspicious they look over time. It never hooks the keyboard or captures keystrokes — it's the detector, not the thing detected.

Three gated signal layers: a rule engine with temporal persistence and risk decay; a RandomForest trained on ClaMP (5,210 labelled Windows executables, 67 PE-header features); and an import-table fingerprint mapped to MITRE ATT&CK. ML can only amplify a rule-based trigger, never create one.

PythonWindowsscikit-learn

SIEM-Project — Attack Chain SIEM

A stateful correlation engine that raises an incident only when a full chain appears in order inside a time window: access anomaly → C2 beacon → objective behaviour.

Beacons are found by interval-variance analysis rather than ML, so every flag can be walked through by hand. Tests assert the negative cases as hard as the positive ones — restraint is the point.

Python (stdlib only)

wazuh-investigations

A SOC home lab with both sides in one repo: a stateful, MITRE-mapped adversary telemetry generator (T1110.001 brute force into T1003.001 LSASS dumping), and the investigations from pointing Wazuh at it — alert triage, false-positive root causes, and the detections that didn't fire, each with the rule needed to close the gap.

A modular recon framework for CTFs, HTB and authorised engagements: ten pipeline stages from port scan to SSL/TLS to screenshots, ending in a self-contained HTML report. Tools are probed before use, every command runs under a timeout, and output never overwrites.
